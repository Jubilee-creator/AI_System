# /tdd

Purpose:
Build features using test-driven thinking (reliable, not fragile).

Use when:
Adding new features or fixing important logic.

---

## PROCESS

1. Define expected behavior
- What should happen?

2. Simulate test case
- Inputs → expected outputs

3. Implement solution
- Write minimal code

4. Validate result
- Does it match expected?

5. Refine
- Improve only if needed

---

## RULES

- Keep logic simple
- Avoid overengineering
- Focus on correctness first

---

## OUTPUT

- expected behavior
- implementation
- result
- validation
